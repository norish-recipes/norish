# 01 — The AI SDK line moves to 7

Status: ready-for-agent
Blocked by: None — can start immediately

Spec: `.scratch/decision-model/spec.md`

## What to build

Norish's AI dependencies move from the AI SDK 6 line to 7, with **no behaviour change**: every import, every enrichment kind, transcription and image generation do after the move exactly what they did before. This is the prerequisite for the Decision Model, because `experimental_evaluate` and the `@ai-sdk/typesafe-ai` provider exist only on the 7 line (`@ai-sdk/provider` 4, the V4 specification). It ships as its own PR.

Read the SDK's 6 → 7 migration guide first and list every breaking change that touches Norish before changing a line. The four places the move can bite, all inside `packages/shared-server/src/ai/runtime/`:

- `temperature-fallback.ts` — a middleware written against the V3 model interface. ADR-0014's behaviour (ask for temperature, drop it when refused) must survive verbatim; its two test files are the contract.
- `runtime.ts` `requestObject` — `generateText` with `Output.object({ schema })` and the plain-JSON degrade path for OpenAI-compatible endpoints (#538). `structured-output.test.ts` is the contract.
- `runtime.ts` `transcribeWithProvider` — `experimental_transcribe`.
- `runtime.ts` `generateImage` — `generateImage` from `ai` and the image-model factories in `providers.ts`; `image-generation.test.ts` is the contract.

ADR-0024 and the Image Generation provider enum carry a note to **re-check which providers expose an image model when the AI SDK line moves**. Do that check and record the outcome in the ticket comments; if a provider gained an image model, that is a follow-up ticket, not this one.

`packages/api`'s recipe extraction (`parser/recipe-extraction.ts`, `image-extraction.ts`) goes through the runtime and should need nothing, but its tests are part of the gate.

The E2E fake provider (`apps/web/__tests__/e2e/harness/ai-provider.ts`) speaks the OpenAI-compatible wire format; if the 7-line `@ai-sdk/openai-compatible` changes what it sends, the fake follows.

**Fallback.** If this turns out to be more than roughly a week of work, or a 7-line provider package is missing a capability Norish depends on, stop and record why in the comments. The spec names the escape hatch: build `decide` on TypeSafe's official `@typesafe-ai/sdk` inside `providers.ts` and leave the line where it is. Ticket 04 is written so either route satisfies it.

## Acceptance criteria

- [ ] Every AI SDK package in `packages/shared-server/package.json` (and any other workspace that lists one) is on its 7-line major; `pnpm-lock.yaml` is regenerated by pnpm, never by hand.
- [ ] No feature file imports anything from `ai` or an `@ai-sdk/*` package (ADR-0015 still holds; `rg` is the check).
- [ ] The temperature-fallback tests, the structured-output tests, the image-generation tests, the extraction tests and the queue worker tests pass unchanged, or with changes that only follow renamed SDK types.
- [ ] The plain-JSON degrade for `generic-openai` / `lm-studio` still triggers on a refused JSON-schema request (#538 test).
- [ ] The E2E AI suite (`apps/web/__tests__/e2e/ai/`) passes against the fake provider.
- [ ] The ADR-0024 image-provider re-check is recorded in this ticket's comments.
- [ ] Nothing a self-hoster configures changes; if it must, an Upgrade note is written.
- [ ] Repo gates green: lint, full test run, internationalization check, production build.

## Non-goals

- Anything TypeSafe. That is tickets 03 and 04.
- Adopting new 7-line features (agents, workflows, new output modes) beyond what the move requires.
