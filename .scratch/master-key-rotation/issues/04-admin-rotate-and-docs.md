## Comments

- **Pending rotation:** the new `previous` is whichever key-file key the database's fingerprint names (boot's own `keyWithFingerprint`), so a rotation still waiting for its boot, or two in a row, keeps the key the data is on and drops the unbooted `current`. No fingerprint, or no key that matches it, refuses and leaves the file alone. Env mode is `masterKeyPinned()`, which reads the same `pinnedKeys()` boot's `keySource` does.
- Refusals answer `{ success: false, error }` like `restoreDefault`. The card reads `admin.getMasterKeySource` (`{ pinned }`) and shows neither the button nor the env note until it answers. The restart modal now takes its copy, so both confirmations share it and its `restart: always` line.
- **tRPC left unticked for one clause:** there is no Demo Instance in the code yet (`DEMO_MODE` is only specced in `.scratch/demo-instance`). Its ticket 01 refuses every mutation in one middleware, which will cover this procedure too.
- Web and mobile needed no client change: a session the re-key ended comes back as tRPC 401, a 4401 socket close, or a session read with no session, and Session Expiry leaves for sign-in (web `/login?callbackUrl=`; mobile `use-mobile-session.ts:59`, `auth-providers.tsx:31,49`, `trpc-provider.tsx:76-77`). A mobile test pins restart, then no session, then sign-in with no error or toast shown. Not run on a device.
- **E2E:** a `master-key` Playwright project with its own file-mode stack: `MASTER_KEY: ""`, and the harness key written as the key file's `current`, so the first boot adopts it and the worker's repositories open the same key. `ProductionStack.restartAfterExit()` stands in for `restart: always`. Passed 3/3 run alone.
