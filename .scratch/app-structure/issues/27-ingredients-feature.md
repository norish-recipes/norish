# 27: `shared-react/ingredients` and `features/ingredients`

**What to build:** The ingredient catalogue's reads and writes, called inline today by the Ingredients page and `components/ingredients/`, become plain hooks in a new `shared-react/ingredients`. The Ingredients page moves into `apps/web/features/ingredients`; `IngredientPanel` stays shared, since recipes, groceries and the Ingredients page open it. Nothing visible changes. See `.scratch/app-structure/spec.md`, "Settings (the fifth feature)" and the rule against calling tRPC from a component under "State".

**Blocked by:** 23

**Status:** done

- [x] `shared-react/ingredients`, exported as `@norish/shared-react/ingredients`, is a feature: it imports no other feature, and lint enforces it. It holds the catalogue as plain hooks: the Ingredients page's list (infinite, keeping the previous page while the filters change), the kinds, the AI changes (`useAIChanges`, `isOpenChange`), an Ingredient and its writes (update, merge, delete, nutrition correction, icon), the spellings and the icons query. `use-ingredient-cache.ts`'s cache writes sit in the mutations' own options.

## Comments

- Implementation (249e71ac1..55e4daac4): `shared-react/ingredients` holds `useIngredientListQuery`, `useIngredientSearchQuery` (pickers), `useIngredientKinds`, `useIngredientQuery`, spellings, uses, `useAIChanges`/`isOpenChange`, `useIngredientMutations`, the icon hooks (`useIngredientIcons`, `useIngredientIconAddress`, `useIngredientsNamed`, `useIngredientIconMutations`) and nutrition (`useIngredientNutritionQuery`, `useNutritionFoodsQuery`, `useNutritionCorrection`); each write's patch, rollback, refresh and toast sit in `useMutation`'s options. A draft carrying display-only fields (parent names, icon address, merge names) is the mutation's variables; its `mutationFn` sends only the procedure's input.
- `onChanged` is gone from `IngredientPanel` and `ChangedByAIPanel`: a landed edit's refresh (list, kinds, AI changes, `nutritionFor`) is the mutation's `onSuccess`, which also covers the recipe nutrition card's old `onChanged`. Refusal and icon/nutrition failure toasts go through the platform toast (`settings.ingredients.*`, shipped by the root layout) and log under `ingredients:<context>`; `features/ingredients/` needs no `root-messages` exemption, since it reads only shipped namespaces.
- `iconIds` moved to `@norish/shared/lib/ingredient-icon-ids` (the groceries layout's seed and the shared hook both use it). `useFoodsByName` stays in web as a debounce over `useIngredientsNamed`. `IngredientRow` keeps its `memo`: its list is `"use no memo"`.
- Bug found while moving the test off mocks: `IngredientSearch` re-ran its effect whenever `onSearch` changed identity, which looped without the compiler; it hands the search on through `useEffectEvent` (committed with the tests). The page and nutrition tests run over a real query cache and web's tRPC fake; `ingredient-nutrition.test.tsx` moved to `__tests__/components/ingredients/` since the section belongs to `IngredientPanel`.

- Review (Opus 5.5 xhigh, both axes, then a re-review of the first fix round), fixed in 66df1a8b2..e05d78226. The spec axis traced every moved write against the old code and found each payload, patch, rollback, reread and toast equal.

One `refuse`/`fail` path raises a refusal's toast; `NUTRITION_REFUSALS` is in contracts and the server's `CorrectionRefusal` derives from it. `answered` joined `settled` and `wentThrough` in `offline/settled.ts`.

- Bugs fixed with a failing test first: the list showed its empty copy while a changed filter's first answer was pending (older than this ticket; rows kept from the previous filter are dimmed and `aria-busy`, and a read paused Offline shows the empty copy, not the skeleton); the panel's typed name and parent were reset when a filter dropped the open Ingredient mid-edit (the draft resets on the saved values, not a new object). The implementer's `useEffectEvent` in `IngredientSearch` stops a new `onSearch` re-sending the text.
