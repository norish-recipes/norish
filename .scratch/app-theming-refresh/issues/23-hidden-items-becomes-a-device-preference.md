# 23 — Hidden Items becomes a device preference

**What to build:** The hidden list moves off the server-side preferences contract and onto a `norish_hidden_items` device-preference cookie, so every visibility choice in settings follows one rule: it belongs to the device. Screen space is a property of the device — a reader can hide Nutrition Information on a cramped phone and keep it on the desktop — and tickets 16 through 19 already put every other visibility preference on that footing. This ticket removes the one exception, revising ticket 04's "choices follow the reader between devices" decision after the fact. The accepted cost is exactly that sentence: the list no longer follows the reader between devices, and each device is set up once — the same stance every other device preference takes.

Ticket 22's first-paint promise is unchanged and gets simpler. A cookie is precisely what the server can read while producing the HTML, and the two paths with no server pass — the offline bootstrap and a navigation answered by the service worker's cached HTML — read the device's own cookie, no network involved. The server pass over the stored preferences and the localStorage mirror existed only because the list lived server-side; both retire with the move.

The cookie is the one list-valued device preference. Its parse must keep entries it does not recognise rather than collapsing to the default, because ticket 04's carried/selected split depends on unrecognised entries surviving storage: a timers choice while the capability is gated off, or an entry from a newer version, is carried and written back untouched, while consumers act only on the entries they know.

**Blocked by:** 04, 22 — both shipped; this revises where 04 put the list.

**Status:** done

- [x] The hidden list is stored in the `norish_hidden_items` cookie through the shared device-preference helper; absent or empty means everything is shown, and the settings multi-select reads and writes it with no change in what the control offers or how it behaves.
- [x] `hidden` leaves the server-side preferences contract and every consumer of it there. No fallback read of the server value and no migration: a reader who had hidden things re-hides them once per device, the same stance 04 took over the display booleans and 16 over the localStorage keys.
- [x] The carried/selected split survives the move to the cookie: a gated-off timers choice and an unrecognised entry are written back untouched, and consumers ignore entries they do not recognise.
- [x] First paint holds on all three load paths exactly as ticket 22 left it: a server-rendered request carrying the cookie never paints a hidden thing, and neither does a navigation answered by the service worker's cached HTML nor the offline bootstrap — not one frame, no network involved.
- [x] Changing the list in settings applies immediately and the next load honours it from the first frame.
- [x] The server-preferences seed pass and the localStorage mirror from ticket 22 are gone. Like the other device preferences, the cookie is device-scoped rather than account-scoped: it survives sign-out and an account switch on the same browser, exactly as the today's-meals rule does, and no boot-owner keying remains.
- [x] Page-level and context suites pin the same first-frame invariants against the cookie seed, including the self-read the offline shell relies on; the settings suite keeps its multi-select and carried-entry tests with only the storage re-pointed; the user router suite drops its hidden fixtures. There is no server-byte harness case: every hidden-list consumer is client-rendered under the seed, ticket 22's honest limit, unchanged by the move.
- [x] The Hidden Items doc page and the 0.21.0 release notes stop saying the list follows the reader between devices and say per-device instead.

## Comments

- Shipped. The helper grew a list variant — `defineDeviceListPreference` in `apps/web/lib/device-preferences.ts` (comma-joined value; parse dedupes, trims, and keeps unrecognised entries) — and the state machinery in `context/device-preference-context.tsx` widened its generic from `V extends string` to a structural `DevicePreferenceLike<V>`, so both scalar and list definitions ride the same seed / self-read / reconcile / write path. `apps/web/lib/hidden-items.ts` now owns `HIDDEN_ITEMS`, `HiddenItem` and `partitionHiddenItems` (list-shaped), all moved out of the shared server contract; `hidden-items-context.tsx` became a thin wrapper over `createDevicePreferenceContext` that keeps `useHiddenItems()` — the seam every consumer and six component suites sit behind — exactly as it was, plus `useHiddenItemsState()` for the settings write. The `(app)` layout's hidden-items server pass collapsed from session + `getUserPreferences` DB read to one `readFrom(cookieStore)` line, which removes a per-navigation session lookup and DB query; `lib/hidden-items-mirror.ts` and its sign-out clear are deleted. One deliberate loss: the native app used to see a reader's timers hide through the synced server list (it never had a control of its own), and a web cookie cannot reach it — mobile's `useTimersEnabledQuery` now answers with the deployment capability alone.
