# 09: The Search Scope row shows on focus and animates in

**What to build:** Mike, 2026-11-20, from his iPhone: the Search Scope row "should show if the search is focused and animate in nicely". The spec said "shown only while the field has text"; this replaces that line.

**Blocked by:** 08

**Status:** code done and checked on the iPhone 18 Pro simulator (light); open: Mike's iPhone (the missing-row cause is from reading the code, not seen on a device), dark mode, the repo-wide gates

- [x] The Scope row shows whenever the field is focused, with or without text, and while the field has text with the keyboard down (results). It is hidden on the rested page (no focus, no text).
- [x] It settles in once the field has finished extending (400 ms after it shows), as one: a fade from a slightly smaller size, no stagger; out in 120 ms. Mike, 2026-11-20, did not like the staggered rise. Reduce Motion: fade only.

- [x] The state rule and its tests say when the row shows; `spec.md`'s Search Scope line updated.
- [ ] Gates green (mobile vitest, tsc, eslint and the Docker deps stage are); checked on the simulator with the software keyboard and its predictive bar, light and dark.

## Comments

2026-11-20: cause of the missing row: `ScopeRow` mounted only once the field had text, after the keyboard's show event, so `useKeyboardHeight` started at 0 and put the row at the tab bar, behind the keyboard. The row now stays mounted (`visible` prop, `showsScope`), the hook starts from `Keyboard.metrics()`, and each chip fades and rises on `useFadeProgress` with a 45 ms stagger. Not seen on a device: the simulator app here has no session. The simulator check (signed in, Release build) then showed the scope chips with the keyboard up and down.

2026-11-20, the × (02's Q5, which asked for a patch or a changed spec): `patches/react-native-screens@4.30.1.patch` (`patchedDependencies` in `pnpm-workspace.yaml`). UIKit's × lowers the keyboard, then selects the previous tab, then calls the bar's Cancel; JS cannot hold the tab (a `disabled` tab keeps Search selected but UIKit then drops the field to the plain tab bar, and `focus()`, `active = YES` and toggling `automaticallyActivatesSearch` do not bring the pill back). The patch notes when the bar stopped editing (0.3 s), blocks the selection away from the search tab in that window, then silently re-selects the search tab through UIKit's setter, which activates its search, and lowers the keyboard again. With the keyboard down the pill has a Home button and no ×-from-typing, so a Home tap still leaves. Seen: × keeps Search, the text and the chips; the pill is tappable again; a second × works; Home leaves. Not seen: a physical iPhone; iOS 26.x (only 27.2 here). On a react-native-screens bump the patch must be re-made (`pnpm patch`), then `pod install` (the package path changes) and a native rebuild.
- Review (2026-11-20, one Opus reviewer): fixed the Docker deps stage not copying `patches/` (it now builds with the patch); the patch emitting focus/blur to JS for its own re-activation, the keyboard-lowering flag outliving a missed wake (it now expires after 1 s), the intercept running without a target tab, the bounce not marked as our own write, the guard not matching RNS's own `RNS_UITAB_API_ENABLED` check; `importantForAccessibility` for the hidden row; the chips no longer rise under Reduce Motion; a stale comment in `use-search-field.ts`. New `maestro/search-close-keyboard.yaml` (× keeps Search, text and scope; the field is active again; Home leaves), 3/3 on the simulator.
- Device feedback (Mike, 2026-11-20, relayed by the auth session; recording of a Release build on his iPhone): (1) the × sometimes did nothing: on the phone UIKit's activation focuses the field after the bounce, the keyboard came back; the patch now keeps an empty input view over the wake (1 s, ended by the first focus), so no keyboard rises, and the focus and blur of the wake no longer reach JS; (2) the pill collapsing and re-expanding glitched: the bounce now runs on the next run-loop turn instead of after 0.1 s; (3) scope chips after the field has extended, no stagger (above); (4) the Search page's title and soft top edge did not follow the scroll like the other tabs' because Discover and Typing were plain ScrollViews: both now use `SearchScroll`, wired to `useTabScroll`. Flake found on the way: a tap on the pill within the wake gave a focused field with no keyboard (window shortened, then ended by the first focus). `search-close-keyboard.yaml` waits for the wake before tapping; 10/10 on the simulator. Not seen on his phone.
- Second device round (Mike, 2026-11-21): "closing animation is good, but the cross inside the input glitches": the clear button rode the field's edge while the pill widened, so the patch hides it for 0.55 s of the wake (and the kept text is put back natively, so UIKit's cancel does not empty the field first). A tap on the pill after the × sometimes found a focused field with no keyboard (the wake's empty input view outliving the wake); `restoreKeyboardAfterWake` now also runs on any focus outside the wake. 8/8 on the iPhone 17 simulator. The re-activation runs inside `performWithoutAnimation`; UIKit's own collapse and widen of the field still play (a short fade).
- Patch rewrite (Mike, 2026-11-21/23: "a hacked together mess"): no timers. UIKit asks to leave the tab in the same run-loop turn the editing ends, so that turn tells the × apart. The patch keeps the text over the cancel, re-selects the search tab on the next turn, presents the search again in `didDismissSearchController:` (the big × shows exactly while the search is presented) and refuses the re-selection's one focus. The bar rides down with the keyboard and the × blinks back after ~0.1 s; Mike chose this over keeping the × with animations off, which snapped the bar halfway. The × with the keyboard down now leaves Search (the pill keeps Home + field + ×). JS no longer blurs on Cancel. Dead ends, from disassembly: `_dismissPresentation:` skips itself when `isBeingDismissed`, but the tab bar collapses the field anyway; `setActive:` is never called on the ×. Each Scope chip's check now draws in and out like the web checkbox (react-native-svg stroke), its slot opening on the app's spring and closing on the stroke's timing. `search-close-keyboard.yaml` 3/3, the other search flows pass, installed on Mike's iPhone 17 Pro.
