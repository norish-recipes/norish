# Scripts

**`measure-page-loads.ts`** times full page loads on a throttled phone. Build with `pnpm build`, start the production server (`PORT=3400 AUTH_URL=http://localhost:3400 AUTH_RATE_LIMIT_ENABLED=false UPLOADS_DIR=… pnpm --filter @norish/web run start`), then run `pnpm --filter @norish/web run measure:page-loads --email … --password …` with an account that has recipes (the newest one rated and a favourite), a cookbook, a planned meal today, priced groceries filed under an aisle, and Pantry suggestions. Each load is a fresh Pixel 7 with the CPU slowed 4×, behind a proxy that shares one 1.6 Mbps down / 750 kbps up link. For every page it prints the median and spread of 15 loads (`--runs`) for first paint, for the first frame each piece of content is drawn in, the document's gzip size and the JavaScript the load downloads (encoded, added up from its script responses), then the time from a tap on a recipe card to that recipe. Add `--sw allow` to install the service worker before each load (`--sw fetch` also turns its navigation preload off), `--share /share/<token>` to include a shared recipe, and `--only /,recipe,tap` to measure some pages.

**`measure-renders.ts`** counts React's mounts and re-renders per scripted action on a dev build, whose components keep their names. Run the server without a watcher, on a database and Valkey db of its own: from `apps/web`, `DATABASE_URL=…/norish_measure VALKEY_URL=redis://localhost:6379/4 PARSER_API_PORT=8401 AUTH_RATE_LIMIT_ENABLED=false PORT=3401 AUTH_URL=http://localhost:3401 TRUSTED_ORIGINS=http://localhost:3401 node --import tsx server/index.ts` (the rest comes from the root `.env.local`). Then `pnpm --filter @norish/web run measure:renders groceries --base http://localhost:3401 --email … --password …`. Give it an account of its own: every run replaces that account's groceries with the script's data set through the API, and it refuses a list holding anything else. Per action it prints each component's mounts and updates, sorted by count, with what changed behind each update: a prop's name, `(state)`, `(context)`, or `(parent)` when only the parent rendered. The `groceries` scenario checks an item, adds one, opens the edit panel, takes the echo of a second signed-in phone checking an item, and switches the view mode. tRPC responses and socket messages reach the page one at a time, in the order they were asked for or sent and at least 150 ms apart, and the page's timers of one delay set within 16 ms of each other fire together, so unchanged code prints the same counts. Each one is a commit of its own, so the commits and updates are a ceiling: a real phone can render messages that arrive together in one commit.
