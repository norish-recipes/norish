# v0.24.0-beta

## Summary

Under the hood, the realtime layer that keeps every household member's screen
in step is rebuilt: one connection to Redis per server, events that were missed
while a browser was disconnected arrive on reconnect, and a restart with
connected browsers completes in seconds. Image generation can now draw through
a local Ollama server, and an optional Decision Model answers the closed
questions among Norish's AI features faster and cheaper than a language model.
The household also gains a Pantry, so a recipe's staples stay off the list,
and Norish offers to import a link you have just copied.

## Features

### Decision Model

An optional second AI provider that answers closed questions and generates
nothing: TypeSafe AI's Jev, configured on its own with its own API key under
**Settings => Admin => AI & Processing => Decision Model**, beside Image
Generation. With one configured, auto-categorization and allergy detection ask
it instead of spending generation tokens, so the bulk sweep costs what the
decisions cost and a newly imported recipe is categorised in well under a
second on a slow local model; Recipe Provenance settles the country and the
Cuisines by it under _Only existing cuisines_, so a Cuisine outside your list
is never invented; a URL that turns out not to be a recipe is refused in
seconds rather than after a failed extraction, and an Instagram caption that
holds the whole recipe is used before a transcription is paid for; and the
products a shop offers for a grocery are ranked, with the model's pick linked
and priced when it is likelier than every alternative together. Every
enrichment run's own output is checked before it is written, while anything a
person entered is never touched.

Everything is selected the moment a Decision Model is configured, and one
multi-select deselects what it should leave to the AI provider. Nothing needs
it: without one every feature behaves exactly as before. See
[AI provider](../configuration/ai-provider.md#decision-model).

### Pantry

Tell Norish what you already have at home, and a recipe's staples stay off
your grocery list.

- Open **Pantry** from the menu on the Groceries page and type what is in the
  cupboard: olive oil, salt, flour. The list is shared with your household.
- When you add a recipe to your groceries, the ingredients you have are shown
  apart under **In your pantry**, unticked, and left off the list.
- Out of something after all? Tick it and it is added with the rest.
- A name matches only when it **is** a pantry name; nothing is guessed from
  words, and no AI is involved.

See [Pantry](../groceries/pantry.md).

### Import from a copied link

Copy a recipe's address anywhere, come back to Norish, and whichever page you
are on asks whether to import it: the link, and an **Import** button that
queues the import exactly as the URL dialog would and takes you to the
dashboard. A tab asks about a link once, so one you passed on is not raised
again, a link into your own Norish is never offered, and offline the import is
Queued like any other change. The ask needs a browser that hands the clipboard
over without a paste, which Chrome, Edge and the other Chromium browsers do
once you have allowed Norish to read it; on Safari and Firefox a copied link
keeps turning up in the URL dialog's prefilled field instead. See
[Importing recipes](../recipes/importing.md#from-a-copied-link).

## Fixes and Improvements

- **Missed events arrive after a reconnect.** A browser that loses its
  connection for a moment, a phone through a tunnel, a laptop lid closed for
  a minute, receives what happened in the meantime when it comes back, in
  order and without a reload, before live events resume. Only a gap too large
  to replay falls back to a full refetch.
- **A server restart with connected browsers completes in seconds** rather
  than waiting out a thirty-second shutdown timeout for sockets it never
  closed. Every open socket is told the server is restarting, and browsers
  reconnect on their own once it is back, with a short random delay so a
  household's devices do not all reconnect at once.
- **The number of Redis connections the server holds no longer grows with the
  number of open browser tabs.** One subscriber connection serves every
  household member.
- **A grocery change that failed validation tells only the person who made
  it**, not the whole household.
- **On a phone, a message confirming what just happened no longer appears
  behind the status bar** or the Dynamic Island when the app is installed to
  the home screen.
- **The startup banner prints the WebSocket path the server actually serves.**
- **Ollama can draw.** Image generation gains Ollama as an Image Provider, for
  an Ollama server running one of its image models such as `x/z-image-turbo`.
  It takes an endpoint and no key, and borrows the endpoint from your AI
  configuration when that is Ollama too, so a fully local setup can now
  generate pictures without a second vendor. See
  [AI provider](../configuration/ai-provider.md#image-generation).
- **The job monitor names the model.** A job's details list every model the
  job asked, the Decision Model or your AI provider, with the model id that
  answered, and mark a request that failed, so which model handled a job is
  visible without reading the logs.
- **A store lookup's job shows its reasoning.** Its search step records how
  many products the shop offered and which one was linked; when the Decision
  Model was asked, the five options it rated likeliest with the probability of
  each and the chance it gave "none of these"; and when it was not, why: the
  name rule linked first, no Decision Model or Grocery linking is off, or the
  request failed. A Miss is told apart from a job that stopped early.
- **Planned recipes show their picture again.** A recipe whose image lives in
  its gallery, which is every recipe imported or created since the gallery
  became the primary slot, rendered as a placeholder on the calendar and the
  dashboard's Today cards. The calendar now resolves the thumbnail the same
  way the recipe library does. ([#581](https://github.com/norish-recipes/norish/issues/581))
- **A check-off made on a shaky connection no longer comes undone.** When a
  grocery change failed to reach the server without the app ever counting the
  backend as offline, it was held for replay but nothing replayed it, and the
  next routine refresh erased it from the list. Such a change now asks the
  server whether it is reachable straight away and is delivered on the first
  answer that says so. ([#565](https://github.com/norish-recipes/norish/issues/565))
- **A recipe planned from the dashboard reaches the calendar page at once.**
  The calendar page's view of the weeks around today is kept ready while you
  are elsewhere in the app, and a recipe planned from the dashboard or a
  recipe card reached that view only through its next successful refresh, so
  a plan could show up late, or not at all until a hard reload. What you plan
  now lands in every kept view the moment the server confirms it, as does
  what other household members plan. ([#583](https://github.com/norish-recipes/norish/issues/583))
- **Recipe videos can be watched full screen on a phone.** The recipe photo
  dissolves into the page and the title is drawn over its lower half, which
  covered the video player's own controls: a video could only be seen cropped
  into the header's shape and without sound, and tapping it merely paused it.
  A recipe whose header is a video now carries an **expand** button beside the
  back arrow. It opens the video full screen, showing the whole frame rather
  than the crop, with its sound on and its progress bar, mute and exit within
  reach, and it keeps playing from where it was on the way in and on the way
  out. On a wide screen the player's own controls were never covered and are
  unchanged. ([#563](https://github.com/norish-recipes/norish/issues/563))
- **A grocery with a measure and one without are no longer added up.** In the
  grouped list, "300 g heavy cream" and a plain "heavy cream" folded into a
  single row reading "301 g", a quantity neither line asked for. A row of the
  grouped list is now one name measured one way: lines measured the same way,
  however the unit is written, still add up under one row, while a line
  measured differently, or not measured at all, keeps a row of its own.
  ([#562](https://github.com/norish-recipes/norish/issues/562))

- **Structured imports recognise more sites.** The parser's recipe-scrapers
  library moves to 15.12.0: some seventy sites are newly read structurally,
  among them Edeka, Jow, Albert, The Guardian, Donna Hay, 177 Milk Street and
  Ricardo Cuisine, ingredient groups are read on dozens more, and a yield
  written as "makes 12 muffins" is understood. leanandgreenrecipes.net is no
  longer supported upstream.

## Upgrade notes

- **WebSocket connections now check their origin.** An upgrade request whose
  `Origin` is not `AUTH_URL`, an entry of `TRUSTED_ORIGINS` or the request's
  own host is refused with `403`. Most setups need nothing; if Norish is
  reached through a reverse proxy that rewrites `Host` or `Origin`, or from
  more than one public address, list every public origin in `TRUSTED_ORIGINS`
  (see [Server runtime](../configuration/server-runtime.md)). The new
  [WebSocket & realtime](../configuration/websocket.md) page has the proxy
  snippets for nginx, Caddy and Traefik, and the idle timeout the proxy must
  exceed.
- **The mobile app is parked and unsupported on this release.** It is not
  maintained against the rebuilt realtime layer and is expected to break
  until its rewrite ships. Use the web app on a phone in the meantime.
