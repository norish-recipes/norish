# v0.20.0-beta

## Summary

This release makes the Norish web app work offline. Pages you rely on keep
working when your server is unreachable — on flaky Wi-Fi, on the move, or
while the backend restarts — and changes you make while offline are saved on
your device and sent automatically once the server is back. The groundwork
also tightens grocery duplicate handling and hardens account switching on
shared browsers.

## Features

### Web app works offline

- The web app now keeps a guaranteed offline set on your device: your 50 most
  recent recipes in full (including each recipe's main photo), all groceries
  and recurring groceries, your stores, and the calendar's initial window. It
  is refreshed automatically in the background whenever the app is connected.
- Changes made while offline — adding or ticking groceries, editing recipes,
  planning meals, importing from a URL, uploads included — are queued safely
  on the device and sent automatically when the server is reachable again.
  The app only reports a change as "Queued" after it is durably stored.
- You can open the app while your server is down — even pages you had not
  visited in that browser yet. The dashboard, warmed recipe details,
  groceries, and calendar boot straight from the offline copy; anything
  outside the offline guarantee shows a clear "offline unavailable" screen
  instead of a broken page.
- A Live/Offline indicator in the user menu opens a status view showing the
  connection state, what is cached, and any queued changes, with retry and
  discard controls. Failed syncs are parked visibly — never silently dropped
  — and conflicting edits follow a first-writer-wins rule you can reapply by
  hand.
- Duplicate-safe syncing: every queued change carries an operation id, so a
  change is applied at most once even if it has to be resent.

### Safer sign-out and account switching

- Signing out with unsynced offline changes now opens a confirmation that
  explains what would be discarded. Cancel keeps everything; signing out
  clears the queued changes and this device's offline copy of your account.
- If the signed-in account changes outside that dialog (for example in
  another tab on a shared browser), the previous account's offline data and
  images are hidden immediately and its queued changes are kept dormant —
  they sync only after that account signs in again, and never as anyone else.

## Fixes and Improvements

### Groceries

- Matching groceries now merge consistently everywhere: the list you see
  while offline applies the same merge rule the server uses, so adding an
  item you already have bumps the amount instead of creating a duplicate row.
- Adding several matching items in one batch (for example from a recipe's
  ingredient list) now accumulates into a single row correctly.
- Grocery syncing survives concurrent edits from other household members:
  if the server merges your queued item into an existing row, follow-up
  changes automatically target the right row.

### Recipes and imports

- Recipes you create while offline become offline-available immediately,
  without waiting for the next background refresh.
- Importing a recipe from a URL while offline now shows the friendly
  "Queued" notice instead of an error, and runs when you are back online.

### Mobile

- Fixed the mobile app build after the Expo SDK update.

## Upgrade notes

- The `LEGACY_RECIPE_PARSER_ROLLBACK` setting has been removed. The
  structured recipe parser has been the default since its rollout; if you
  still set this variable, delete it from your environment.
- No manual database steps: schema migrations run automatically at startup,
  as usual.
