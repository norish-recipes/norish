# v0.20.0-beta

## Summary

This release is focused on making the web app work offline, introduces recipe provenance and improves on several (AI) workflows.

## Features

### AI recipe enrichment

📖 [Recipe enrichment](../recipes/enrichment.md)

- Every recipe now enters the same 'enrichment' flow after it is saved.
  Previously what you got depended on how the recipe entered Norish: a link
  import that AI had to read skipped the background work entirely, pasted
  recipes got two of the four, image imports got none, and a recipe you typed
  in got nothing at all.
- Speed over completeness in this case, first we create a recipe that is useable. Enrichment is enrolled separately and cannot
  delay a save, undo one, or turn a successful import into a failure.
- **Six switches** under **Settings => Admin => AI**: auto-tagging,
  allergy detection, auto-categorization, nutrition estimation, **recipe
  provenance** and **ingredient linking**.
  When a switch is turned on, the option runs automatically when a recipe is imported.
  Manually running them is possible even when the feature is off.

### Recipe provenance

📖 [Recipe provenance](../recipes/provenance.md)

- Norish can now work out **where a recipe originates from**.
- The country's name and the explanation are written in **the language the
  recipe itself is written in**: an Italian recipe gets an Italian note beside
  its Italian steps, and a Dutch recipe about a Turkish dish is titled
  _Turkije_ because both are recipe content, not interface text, and are
  never translated. Pick a country by hand and the label you picked is stored
  in your own words.
- When several countries claim a dish, inference picks the single strongest claim and acknowledges the rivals
  in the note.

### Ingredients in cooking steps

📖 [Step ingredients](../recipes/step-ingredients.md) · [Creating and editing recipes](../recipes/creating-and-editing.md)

- A step can now carry the ingredients it uses, shown beneath the step.
  _"add half the water"_ reads **25 ml water** when the line is 50 ml, so the
  arithmetic is never yours to do.
- Amounts are computed at the moment you read them, from the live ingredient
  line: they follow every edit, the active measurement system, and the
  servings control. A line with no amount shows its name only.
- In the recipe form, every step has a chips row: type `@` to mention an
  ingredient.
- An entered amount is kept as the equivalent share of its line, so it scales
  with the servings control and follows the measurement system like every
  other step ingredient.
- The old render-time `@`-token linking in step text has been **retired** in its
  favour. Legacy `@` tokens in stored recipes now read as the literal text they
  always were; nothing is migrated or rewritten.
- In the admin settings **Settings => Admin => AI** it is possible to turn on automatic inference of steps so that they are automatically linked as a background job using AI.
  📖 [Letting AI fill the gaps](../recipes/step-ingredients.md#letting-ai-fill-the-gaps)

### Web app works offline

📖 [Use Norish offline](../offline.md)

- The web app now keeps a guaranteed offline set on your device: your 50 most
  recent recipes in full (including each recipe's main photo), all groceries
  and recurring groceries, your stores, and the calendar's initial window. It
  is refreshed automatically in the background whenever the app is connected.
- A Live/Offline indicator in the user menu opens a status view showing the
  connection state, what is cached, and any queued changes, with retry and
  discard controls.
- Duplicate-safe syncing: every queued change carries an operation id, so a
  change is applied at most once even if it has to be resent.
- Opening the app on a very slow connection no longer hangs on the splash
  screen: if your server has not answered within five seconds, Norish shows
  the saved copy of the page.

## Fixes and Improvements

### Meal planning

- Adding a recipe to the calendar from its own page works again. The slot menu
  opened over the panel but no longer responded to a tap, so nothing was ever
  planned. The same fault turned out to affect every menu, dropdown and date
  picker opened inside a sliding panel — the slot menu was simply the one most
  people met — so all of them now respond again: the slot and date fields when
  editing a planned recipe or note, the store picker when adding or editing a
  grocery, and the expiry picker when sharing a recipe
  ([#511](https://github.com/norish-recipes/norish/issues/511)).

### Recipes and imports

- **Instagram reels are no longer mistaken for photo posts.** Detection asked
  yt-dlp for a duration and treated its absence as "no video", but whether a
  reel reports a duration depends on the yt-dlp version and the extractor path
  it takes, so on some instances every reel fell back to reading the caption,
  losing the video and the creator and failing outright on reels whose caption
  is not a full recipe. Norish now asks whether the post has a video stream,
  and a post it cannot classify is downloaded rather than assumed to be a
  photo ([#513](https://github.com/norish-recipes/norish/issues/513)).
- **Extraction works on models that reject `temperature`.** Newer models —
  Anthropic's `claude-sonnet-5` among them — answer any request carrying a
  temperature with an error instead of ignoring it, which failed the import
  before the model ever read the prompt. The AI provider packages have been
  updated to versions that know those models and leave the parameter out, and
  a model that still refuses one — a brand new release, or whatever you run
  behind an Ollama, LM Studio or generic OpenAI endpoint — is asked again
  without it, so the configured value stays a preference rather than a reason
  to fail. No setting needs changing.
  ([#514](https://github.com/norish-recipes/norish/issues/514))
- **The yt-dlp version on the admin screen is now a live report, and
  read-only.** It used to be a setting you could edit and save that nothing on
  the server ever read, so it showed the environment value on a fresh install, a
  stale string on an older one, or whatever someone had typed — misleading in
  exactly the moment it matters, since that version is the first thing to check
  when Instagram stops importing. Norish now asks the downloader itself which
  release it is, and says **no yt-dlp binary found** plainly when there is
  nothing to ask. Nothing to migrate: the field could never change which binary
  ran, because the Docker image fixes it and a development install downloads it
  once.
- The AI temperature slider in **Settings => Admin => AI** renders its track and
  handle again, so the value can be adjusted. Thanks to
  [@pannal](https://github.com/pannal)
  ([#499](https://github.com/norish-recipes/norish/pull/499)).

## Upgrade notes

- **API change: `POST /recipes/import/url` now returns an object.** It used to
  answer with a bare recipe id, and with `409 Conflict` when you already had the
  recipe. It now returns `{ "recipeId": "…", "status": "queued" | "exists" }` —
  `exists` carrying the id of the recipe you already hold, so a client can open
  it instead of reporting a failure. A `409` now means only that an import of
  that URL is already in flight. Scripts that read the response as a plain
  string need updating; the browser extension is updated to match.
- **Recipe enrichment**: We tried to migrate automatically but please check in the admin settings whether your old settings still apply.
  New enrichment modes are turned off by default.
- **Inline `@`-token linking in step text is retired.** Steps that contain
  literal `@ingredient` tokens render them as plain text from now on; the links
  themselves now live beside the step as step ingredients. Nothing is migrated:
  re-attach with the editor's chips, or run **Link Ingredients to Steps** on
  recipes whose steps have no links yet.
- The `LEGACY_RECIPE_PARSER_ROLLBACK` setting has been removed. The
  structured recipe parser has been the default since its rollout; if you
  still set this variable, delete it from your environment.
