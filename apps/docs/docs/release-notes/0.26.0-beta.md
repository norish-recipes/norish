# v0.26.0-beta

## Summary

This release focuses on improving existing workflows. Your Library, recipes, cookbooks and groceries load up to 14 times faster on a slow phone, the Docker image is about 30% smaller, and administrators can cancel running background jobs. AI can clean up the ingredient catalogue and fill in missing nutrition, conversions and icons. Page imports can fall back to a Chromium browser or a challenge solver when a site blocks them, and you can link more than one sign-in method to your account.

Norish now runs on Node.js 26, replaces Redis with Valkey, an open-source implementation of Redis, and updates its dependencies. It also fixes several security issues. Read the [upgrade notes](#upgrade-notes) before updating.

ALso the readme is modernised and the landing page is once again redone, this time i'm finally happy.

## Security

Update as soon as you can. This release fixes several security issues:

- **Video links:** a recipe's video link could pass command-line options to yt-dlp, which let a signed-in user run code on the server ([GHSA-732x-jh4x-wg8j](https://github.com/norish-recipes/norish/security/advisories/GHSA-732x-jh4x-wg8j)). Only http(s) links reach yt-dlp now.
- **Recipe pictures and videos:** any signed-in user could add or delete pictures and videos on any recipe, and an upload could write files outside the uploads folder.
- **Private pictures:** any signed-in user could open another household's recipe, step and cookbook pictures by their address, and a shared cache in front of Norish could hand them to anyone.
- **Recipe imports:** an import link could name a local file or a server other than a website (`file:`, `gopher:`), and a link written with a backslash could pick up one site's sign-in tokens and send them to another.
- **Site authentication:** a header token was sent to every other site a page import loaded scripts from, and never with the page itself.
- **Site authentication domains:** a token saved for a bare word like `instagram` was sent to every site with that word in its address, like `instagram.evil.com`. A token takes a full domain now, like `instagram.com`, and a bare-word token is no longer sent.
- **Export:** a server admin whose role was taken away could still export every recipe on the instance until they signed out.
- **Sign-in rate limits:** behind more than one reverse proxy, everyone shared one sign-in rate limit. List your proxies in `TRUSTED_PROXIES` to give each visitor their own (see [upgrade notes](#upgrade-notes)).
- **Sign-in tokens:** the tokens Google, GitHub or your OIDC provider hand out at sign-in were kept in the database in plain text, the OIDC one with the user's email and name in it. They were never used, so they are no longer stored.

## What's new

### Ingredient catalogue

Find the new options under **Settings => Admin => AI & processing => Ingredient catalogue**.

- **Automatic AI for new ingredients:** When a new ingredient is added to the catalogue, AI can clean it up (merge it into the food an existing item, clean up the name or delete it when it is not a food), estimate missing nutrition and conversions, and draw an icon if missing.
- **Clean up catalogue** runs AI over the ingredients you already have: only the ones nobody reviewed yet, or the whole catalogue. 
- **Fill gaps** fills missing nutrition, conversions and icons for every ingredient missing any of these.

See the [ingredient catalogue documentation](/groceries/ingredients#ai-cleanup).

### Recipes and groceries

- Import a recipe from a PDF.
- Filter recipes by the ingredients you already have in your Pantry.
- Print a recipe or save it as a PDF, with your chosen servings and measurements.
- Scale a recipe from 0.5x to 4x, or enter a custom serving count or multiplier. The panel opens by clicking on the amount.
- Recipe imports preserve ingredient sections and handle more ingredient amounts, units and source formats.

See the [recipe importing documentation](/recipes/importing#from-pasted-text-or-photos) and [recipe page documentation](/recipes/recipe-page#print-a-recipe-or-save-a-pdf).

### Page renderers and fallbacks

- Configure page renderers under **Settings => Admin => Page renderers**: Obscura (endpoint, token and timeout), Chromium browser (CDP) and FlareSolverr or Byparr.
- When Obscura can't read a page, for example because Cloudflare shows a challenge, we fall back to the Chromium browser and then to the solver. This applies to URL imports, grocery prices and Instagram captions. Any renderer not setup is skipped of course.
- Site authentication tokens are sent to the Chromium browser like they are to Obscura, but never to the solver.
- Any Chromium with a CDP endpoint works. Norish publishes `norishapp/chromium` as a commented-out service in the example compose file.

See the [recipe parser documentation](/configuration/parser#page-renderers).

### Accounts and sign-in

- Link more than one sign-in method to your account under **Settings => User => Sign-in methods**: your server's OIDC provider, Google or GitHub. The provider's email doesn't have to match your account's, and you can disconnect a method as long as one remains.
- **Change password** now signs you out on your other devices.

Thanks to [@QuirkyTurtle94](https://github.com/QuirkyTurtle94) ([#668](https://github.com/norish-recipes/norish/pull/668)). See the [authentication documentation](/configuration/authentication#linking-accounts).

### Administration and integrations

- Administrators can cancel running background jobs and retry them if needed.
- The import API provides a status URL to follow an import through to completion.
- Norish can run under a sub path such as `https://example.com/norish`. Build the image with the path and set `AUTH_URL` to the same address. See [Server & runtime](/configuration/server-runtime#base-path). Thanks to [@x84a01](https://github.com/x84a01) ([#651](https://github.com/norish-recipes/norish/pull/651)).

## Upgrade notes

Breaking changes:

- **Valkey replaces Redis.** Norish now uses Valkey. Update your Compose configuration and `VALKEY_URL`. Pending background jobs are dropped during the switch, and users will need to sign in again once. Redis is still supported and will remain so, however examples will use valkey from now on.
- **OIDC callback URL:** Update your identity provider's redirect URI to `/api/auth/callback/oidc`. This is a change in better auth.
- **Sign-in method linking:** A second provider with the same email no longer links to an account automatically. Connect additional providers through **Settings => User => Sign-in methods**.
- **Site authentication tokens:** Tokens must use a full domain, such as `instagram.com`, rather than a bare name. Re-add affected tokens in Settings.
- **Configuration changes:** Review the notes for edited ingredient words, units, recurrence words, content indicators and AI prompts. Some custom settings do not automatically gain the new defaults.
- **API changes:** The recipe API now uses `images` for recipe pictures; 
- **Health checks have moved:** to `/api/v1/health/live` and `/api/v1/health/ready`. `/api/v1/health` still works and answers like ready, but is deprecated.
- **Private addresses:** Page imports and shop pages block private-network addresses by default. Enable the documented setting only if you intentionally need to access services on your own network.

Read the detailed [server and runtime documentation](/configuration/server-runtime), [authentication documentation](/configuration/authentication#linking-accounts), [recipe importing documentation](/recipes/importing#through-the-api) and [AI provider documentation](/configuration/ai-provider#ingredient-catalogue) before upgrading if you rely on custom configuration or API integrations.
