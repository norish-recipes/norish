Updated July 29, 2026 · branch feat/web-offline-safe · source decisions in docs/adr/offline · docs/adr/releases · docs/adr/recipes

Norish web targets flaky connectivity and backend-down page loads with a persisted Warm Set and a durable mutation Outbox. This summary also records the release-notes checkpoint workflow completed for 0.20.0-beta.

The Offline guarantee is intentionally narrow. It supports short outages and flaky connections, including creating groceries and checking existing groceries off. It is not a general local-first editing model.

Implemented decision record

Offline reads

TanStack Query state is persisted to IndexedDB. While Live, the Cache Warmer maintains the Warm Set: 50 recent full recipes, all groceries and recurring groceries, stores, and the calendar's initial window. Primary recipe images share Serwist's bounded cache and expiration bookkeeping.

Offline writes

Unreachable tRPC mutations enter a per-user IndexedDB Outbox and Replay FIFO after recovery. Queued is reported only after the write succeeds, and ordered FormData entries are reconstructed for Replay.

Replay safety

Operation ids provide generic duplicate safety. Client-minted ids cover the normal create path. Replay id rewriting remains rejected; a server-side grocery merge can make a follow-up change to that still-unsynced create fail.

App Shell

Serwist owns the service worker, its content-hashed precache, runtime image cache, and navigation fallback. A provider-backed bootstrap renders unseen Warm Set routes and an explicit Offline-unavailable state elsewhere.

Conflict policy

Replay remains strict FIFO. Stale successful writes are parked visibly as Conflicted; first writer wins and field-wise force merging remains deferred.

Security posture

Device possession grants Offline read access. Sign-out warns before discarding queued work, while account switches gate rendering until the incoming cache owner is isolated.

Decisions (ADRs)

  • ADR-0001 — Web offline is a persisted query cache

    Persist the TanStack Query cache and use a Cache Warmer; offline search remains degraded by design.

  • ADR-0002 — Replay idempotency via operation ids

    Use one path-agnostic operation-id middleware and Redis TTL claims to make Replay duplicate-safe.

  • ADR-0003 — Client-minted entity ids on create

    Hero creates accept optional client UUIDs so queued create-then-edit chains remain valid; Replay id rewriting is rejected in this historical record.

  • ADR-0004 — First-writer-wins Replay conflicts

    Stale writes park visibly as Conflicted; field-wise conflict merging remains deferred.

  • ADR-0005 — Offline security posture

    Device possession grants Offline read access; Offline sign-out is disabled and account switches purge scoped cache and Outbox state with a warning.

  • ADR-0006 — Serwist owns the service worker

    Content-hashed precaching and navigation fallback replace the hand-rolled service worker version pipeline.

  • ADR-0007 — Forced Offline is development-only

    The debug toggle faithfully blocks transport and does not ship as a production user feature.

  • ADR-0008 — New recipes join the Warm Set

    A newly created recipe is durably offline-available without waiting for the next warm pass.

  • ADR-0009 — Offline guarantees are end-to-end

    Accepted and implemented. Durable admission, provider-backed Offline routes, bounded warm media, identity isolation, and a deliberately narrow grocery guarantee.

  • ADR-0010 — Release notes use a release checkpoint

    Accepted and executed. A thin docs-version command, practical release checkpoint, usual-style notes, and production docs validation.

  • ADR-0011 — Recovery reconciles after terminal Replay

    Implemented. Realtime remains the fast path; one post-Replay active-query refetch is the cache-consistency guarantee.

  • ADR-0012 — Cuisines and Tags share a shape and differ in governance

    Accepted. Cuisines are a curated vocabulary in their own table; Tags stay an open folksonomy. Rejects a database enum, a config list, and reusing Tags.

  • ADR-0014 — Norish never claims to know a model's parameters

    Accepted. The unpopulated capability table is deleted; a refused Generation Preference is dropped at runtime. Rejects maintaining a table of model ids.

  • ADR-0015 — Norish issues every model request through one runtime

    Accepted and implemented. The caller-less executor is deleted and rebuilt as the AI Runtime: one seam for structured generation and transcription, typed thrown errors carrying retryability, enrichment features in shared-server, extraction with the parser. Rejects adopting the executor, a dedicated AI package, and a result union.

  • ADR-0016 — Prompts are appended to, never interpolated

    Accepted and implemented. The runtime accepts a prompt name plus appended sections, never a finished string, so a hardcoded prompt is unrepresentable; new input arrives appended so customised prompts survive upgrades. Rejects placeholder templates for new content and image extraction's string surgery.

  • ADR-0017 — The prompts row stores only overrides

    Accepted and implemented. The stored prompts row carries only texts that differ from the shipped defaults; reads merge over the shipped files, saves strip default-equal fields, and boot prunes legacy rows against every default any release shipped. Rejects seeded default copies and the row-level isOverridden freeze.

  • ADR-0018 — Automatic provenance fills the group's gaps

    Accepted and implemented. Automatic Recipe Provenance keeps every supplied slot and fills only the absent ones; inference receives the supplied slots as settled facts, and only a complete group suppresses the run. Rejects whole-group suppression by any single value, merging blind to the model, and append-merging supplied Cuisines.

Validation policy

  • Browser-level evidence is mandatory for service-worker navigation, IndexedDB, Cache Storage, account transitions, and backend-down behaviour.
  • Focused contract tests pin Outbox serialization, durable admission, grocery rollback, account isolation, and image-cache expiration bookkeeping.
  • Web and tRPC typechecks, the production web build, the browser suite, formatting, and git diff --check are release gates.
  • Release-note validation reviews the generated snapshot, then runs docs formatting, link checks, and a production docs build.
  • Results must distinguish passed, failed, and environmentally blocked validation.

Explicitly out of scope

  • Admin Offline support or admin-procedure idempotency.
  • Canonical grocery-id substitution and guaranteed follow-ups to merged offline creates.
  • Proactive gallery, step-image, or video warming.
  • Arbitrary unseen routes or multi-day local-first operation.
  • Creating a release tag, publishing a GitHub release, promoting images, or deploying docs as part of ADR-0010.
