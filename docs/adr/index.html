Norish Web Offline — Design Recorddecisions locked · not yet implemented

July 20, 2026 · branch feat/web-offline-safe · decided in a grilling session with Mike · glossary in CONTEXT.md, decisions in docs/adr/0001–0006

The web app keeps working when the backend doesn't: cached reads, queued writes, honest status. Targets flaky connectivity and backend-down page loads — explicitly not multi-day local-first.

System at a glance

Reads

The TanStack Query cache itself is persisted to IndexedDB via the shared bundle's getQueryClient seam (mobile's proven pattern). A Cache Warmer guarantees the Warm Set while Live; everything else fetched is kept best-effort. 7-day maxAge, busted on app version.

Writes

Any tRPC mutation failing on unreachability enters the IndexedDB Outbox (structured clone — file uploads included; no whitelist). Queued is a third outcome: optimistic flows keep their state; others toast "saved offline". The Outbox never expires.

Replay correctness

Strict FIFO. Duplicate-safe via a generic operation-id idempotency middleware (Redis, 7-day TTL). Create-then-edit chains survive via client-minted ids on hero creates. Conflicts: first writer wins, loser parked visibly as Conflicted.

Connectivity

Offline = backend HTTP unreachable, verdict by probing public /api/v1/health (excluded from SW caching so it can't lie). WS state is only a hint. Auto-recovery by backoff probes. The full-screen blocking overlay is removed.

UI

Status row at the bottom of the user menu + attention badge on the avatar. Modal: connection state, one-line cache status ("healthy, warmed X ago"), outbox list with retry / discard / sync-now, and the persisted, manual-exit Offline Toggle (radio silence).

Auth posture

Device possession = read access. Sign-out disabled offline; cookie expiry halts sync, never reads; Replay resumes after re-login. Cache + Outbox keyed per user id, purged on account switch (warn if outbox non-empty).

App Shell

Serwist owns the service worker: content-hashed precache (kills the rotted update-sw pipeline), navigation fallback to the cached shell, RSC-aware caching. Custom worker code keeps notification-click + image caching.

Multi-tab

One shared Outbox with transactional appends; Replay + Warmer run in a single Web-Locks-elected leader tab. Cache persistence is last-writer-wins — offline view divergence between tabs accepted; no mutation is ever lost.

Connectivity states

LiveBackend HTTP reachable. Realtime may still be reconnecting — syncing is what counts.
OfflineProbe failed. Serve cache, queue writes, probe on backoff until recovery.
Offline (forced)Toggle on: no probes, no WS, no refetch, no Replay. Persists across reloads; only the user exits.

The Reconnect Sequence

1 · Drain OutboxReplay to completion or halt
→
2 · Invalidate all queriesrefetch server truth
→
3 · Warmtop up the Warm Set

Mandatory ordering — refetching before draining makes queued changes visibly vanish and reappear. The bundle's invalidateOnReconnect is switched off for web and replaced by this sequence.

Decisions (ADRs)

  • ADR-0001 — Web offline is a persisted query cache, not a domain database

    Persist the query cache + Warmer; rejected the prior 31k-line bespoke IndexedDB domain store. Offline search degraded by design; content guarantees are the Warmer's job.

  • ADR-0002 — Replay idempotency via a generic operation-id middleware

    One path-agnostic middleware + Redis TTL claims per x-operation-id. Rejected accept-duplicates and the per-router receipts machinery. Fixes mobile's latent duplicate risk for free.

  • ADR-0003 — Client-minted entity ids on create

    Hero creates (groceries, recurring, stores, calendar items; recipes if cheap) accept a client UUID so queued chains stay valid. Do not "fix" back to server-minted ids.

  • ADR-0004 — First-writer-wins on Replay conflicts

    The version guard stands; dropped offline patches park as Conflicted. Field-wise force-apply deliberately deferred — revisit if lost-tick conflicts show up in practice.

  • ADR-0005 — Offline security posture: device possession = read access

    Reads work across cookie expiry; no cache-at-rest encryption; server authority resumes at the sync boundary. Per-user cache scoping is the non-negotiable part.

  • ADR-0006 — Serwist owns the service worker

    Content-hashed precache + maintained App Router recipes; the hand-rolled sw.js and its silently-broken version pipeline are deleted.

Key seams & reference points

  • packages/shared-react/src/providers/trpc-provider.tsx — the bundle exposes every needed seam: getQueryClient, mutationLink, invalidateOnReconnect, WS callbacks. Web currently passes only logger (apps/web/app/providers/trpc-provider.tsx).
  • apps/mobile/src/lib/outbox/* + apps/mobile/src/lib/query-cache/* — the working reference implementation (MMKV-based; web swaps storage for IndexedDB and adds blobs, leader election, idempotency awareness).
  • packages/shared-react/src/providers/operation-id-link.ts — x-operation-id already attached to every mutation; replays preserve it. The idempotency middleware keys on this.
  • packages/shared-react/src/hooks/optimistic-updates.ts — shouldPreserveOptimisticUpdate is the hook point for Queued-as-tentative-success; calendar's rollback in use-calendar-mutations.ts must learn to skip restore on Queued.
  • packages/trpc/src/routers/config/procedures.ts — config.health (public, OpenAPI /api/v1/health) is the probe target; must be excluded from SW caching.
  • apps/web/components/navbar/navbar-user-menu.tsx — indicator lands in the dropdown footer; avatar already has an update-ping badge pattern to reuse.
  • Branch feat/make-web-offline-safe — the abandoned 31k-line prior attempt. Reference only; zero code reuse.
  • Warm calendar keys via the same helpers the UI uses (apps/web/app/(app)/calendar/context-helpers.ts) — never duplicate range math.

Watch out for

  • The SW currently network-first-caches /api/* GETs — a cached healthy response would lie to the probe. Exclude the health route.
  • Groceries and calendar hooks use different optimistic styles (imperative + reconcile vs snapshot + rollback) — Queued handling differs per style.
  • navigator.onLine measures internet, not the backend — never use it as the Offline verdict, only as a hint.
  • Outbox entries must survive app-version cache busting — only the query cache is busted, never queued human intent.
  • Known pre-existing breakage baseline (zod v3/v4 typecheck errors, 3 db test failures) — diff CI results against baseline, don't expect clean output.
