Updated July 22, 2026 · branch feat/web-offline-safe · source decisions in docs/adr/0001–0010

Norish web targets flaky connectivity and backend-down page loads with a persisted Warm Set and a durable mutation Outbox. This summary also records the release-notes checkpoint workflow. It is a design summary, not evidence that the follow-up work has shipped.

No application implementation is part of this documentation change. ADR-0009 formalizes the remaining review findings and their acceptance tests. ADR-0010 formalizes future release-note generation; it does not create the currently missing docs checkpoint or release-note page.

Implemented decision record — ADR-0001 through ADR-0008

Offline reads

TanStack Query state is persisted to IndexedDB. While Live, the Cache Warmer maintains the Warm Set: 50 recent full recipes, all groceries and recurring groceries, stores, and the calendar's initial window. ADR-0009 records that primary image responses are not yet warmed end to end.

Offline writes

Unreachable tRPC mutations enter a per-user IndexedDB Outbox and Replay FIFO after recovery. The current link attempts a structured clone and starts the IndexedDB write; ADR-0009 specifies the missing durable-admission and FormData guarantees.

Replay safety

Operation ids provide generic duplicate safety. Hero creates accept optional client-minted ids, while ADR-0003 explicitly rejected Replay id rewriting. Grocery merging exposed the follow-up gap captured in ADR-0009.

App Shell

Serwist owns the service worker, its content-hashed precache, runtime image cache, and navigation fallback. The current unseen-route fallback is not the provider-backed Warm Set router specified by ADR-0009.

Conflict policy

Replay remains strict FIFO. Stale successful writes are parked visibly as Conflicted; first writer wins and field-wise force merging remains deferred.

Security posture

Device possession grants Offline read access. ADR-0005 records Offline sign-out as disabled and account switching as a purge operation; ADR-0009 specifies the replacement interaction discovered during review.

Decisions (ADRs)

  • ADR-0001 — Web offline is a persisted query cache

    Persist the TanStack Query cache and use a Cache Warmer; offline search remains degraded by design.

  • ADR-0002 — Replay idempotency via operation ids

    Use one path-agnostic operation-id middleware and Redis TTL claims to make Replay duplicate-safe.

  • ADR-0003 — Client-minted entity ids on create

    Hero creates accept optional client UUIDs so queued create-then-edit chains remain valid; Replay id rewriting is rejected in this historical record.

  • ADR-0004 — First-writer-wins Replay conflicts

    Stale writes park visibly as Conflicted; field-wise conflict merging remains deferred.

  • ADR-0005 — Offline security posture

    Device possession grants Offline read access; Offline sign-out is disabled and account switches purge scoped cache and Outbox state with a warning.

  • ADR-0006 — Serwist owns the service worker

    Content-hashed precaching and navigation fallback replace the hand-rolled service worker version pipeline.

  • ADR-0007 — Forced Offline is development-only

    The debug toggle faithfully blocks transport and does not ship as a production user feature.

  • ADR-0008 — New recipes join the Warm Set

    A newly created recipe is durably offline-available without waiting for the next warm pass.

  • ADR-0009 — Offline guarantees are end-to-end

    Accepted, not implemented. Formal follow-up specification with user stories, browser acceptance seams, standards fixes, and explicit supersession rules.

  • ADR-0010 — Release notes use a release checkpoint

    Accepted, not executed. Formal docs workflow for checkpointing the current release and producing feature-complete, provenance-backed release notes.

Validation policy

  • Browser-level evidence is mandatory for service-worker navigation, IndexedDB, Cache Storage, account transitions, and backend-down behaviour.
  • Focused contract tests pin Outbox serialization, durable admission, grocery merge parity, canonical-id substitution, and image warming.
  • Web and tRPC typechecks, the production web build, the browser suite, formatting, and git diff --check are release gates.
  • Release-note validation inventories every commit in the checkpoint range, then runs docs formatting, link checks, and a production docs build.
  • Results must distinguish passed, failed, and environmentally blocked validation.

Explicitly out of scope

  • Admin Offline support or admin-procedure idempotency.
  • ID-less legacy grocery creates.
  • Proactive gallery, step-image, or video warming.
  • Arbitrary unseen routes or multi-day local-first operation.
  • Creating a release tag, publishing a GitHub release, promoting images, or deploying docs as part of ADR-0010.
