# Store pages are read with a structured-data ladder, not a model

Pricing a Grocery means reading a shop's own website, and the obvious instinct — hand the page to the AI Runtime and ask what it sells — is the wrong tool for it. A supermarket search page is not prose to be understood; it is a list already marked up for Google, and where the markup is missing the price still sits in a machine-readable attribute. We read Store pages with a fixed ladder instead: on a results page, `application/ld+json` `ItemList` for the complete, clean list of names and product URLs, then a DOM pass over the product anchors for the prices, merged on URL; on a product page, `Product` JSON-LD for the authoritative Shelf Price. The evidence for the ladder is the two shops we checked. **Dirk** answers a plain HTTP fetch with an `ItemList` of all 198 results, but attaches `offers` to only the 32 that happen to be on promotion, scattered from position 11 to 193 — so a JSON-LD-only reader shows a sixth of the shelf and not even the first page of it, while its DOM carries a price on all 198 cards. **Albert Heijn** answers a plain fetch with 403, and even fully rendered its results page has no JSON-LD at all and is marked `noindex,nofollow` — Google never sees it, which is why the belief that "Google indexes it, so the data must be there" does not survive contact; the AH cards Google does show come from AH _product_ pages, which do carry `Product` JSON-LD. On AH's results page the price is nonetheless plainly readable in each card's `aria-label` ("Milner Jong belegen 35+ plakken, Nutri-Score D, 150 gram €2.99"). We rejected the model-based reader because it costs a model call per shop visit, demands an AI provider for a feature that is fundamentally string extraction, and fails in a way nobody can debug; we rejected per-shop adapters because they are a maintenance treadmill that supports only the shops we personally wrote code for; and we rejected a JSON-LD-only purist reader because the Dirk numbers show it silently hides most of the shelf.

## Consequences

- Every shop the ladder handles is pinned by a committed fixture of its real HTML, so a markup change fails a named test rather than quietly returning nothing. The first two fixtures are a Dirk results page (198-item `ItemList`, prices only in the DOM) and an AH results page (no JSON-LD, prices in `aria-label`).
- Key matching in JSON-LD must be case-insensitive. Dirk's product pages write `"Price": 7.99` with a capital P inside `offers`, which schema.org does not sanction and which the same site does not do on its results page — a spec-faithful reader finds no price on any Dirk product page.
- Candidates without a price are never offered. That makes the DOM tier load-bearing rather than a fallback: on Dirk, JSON-LD alone would leave 166 of 198 products unofferable.
- Where a page names no products, the DOM tier has to find the shelf itself. It groups the page's links by how deep their path runs and what section it starts in, and takes the group with the most **prices** beside it — not the largest group. Size answers the wrong question: a shop whose search found one product still puts its whole footer of sections on the page, so the more exactly a shopper names what they want the more certainly the footer outnumbers the shelf. Searching AH for a full product name read seventeen Allerhande recipe sections and no products at all, while a vaguer search for the same thing worked. A menu of sections is priced nowhere and a shelf is priced almost everywhere, which separates the two without knowing anything about either shop; a page where nothing is priced falls back to the largest group and keeps a floor of three links, because there a lone link really is indistinguishable from navigation.
- A shop that turns the plain fetch away turns the browser away too. AH answers the rendered visit with an Akamai interstitial — two kilobytes of script that replace themselves with the real page some seven seconds later — so reading the page the instant it loads gets the challenge, every time, and the whole feature reads as "the shop found nothing". The rendered fetch therefore takes the caller's own reading of whether the HTML is the page it asked for and waits until it is. Only a caller can tell: a bot check and an empty results page are the same two kilobytes to everybody else.
- A plain HTTP fetch is tried first and Obscura is the escalation, on 403, on a challenge stub, or on zero candidates. Obscura therefore stays optional for this feature: without it Dirk-shaped shops work, AH-shaped shops do not, and hand-typed Store Products cover the gap. This does not reopen ADR-0019: a plain fetch renders nothing, so Obscura remains the only rendered-page engine, and when a Store page needs rendering it is Obscura that renders it. What 0019 forbids is a _second_ engine or a silent HTTP fallback inside the import path, not an unrendered fetch of a page that does not need a browser.
- A Shelf Price is overwritten, never appended. There is no price history and no way to reconstruct one later — the cheapest decision to make now and the only one here that cannot be undone by a later migration. It is deliberate: the feature shows what a thing costs today, and a history nobody has asked for would double the write path and the storage of every refresh.
- Auto-linking without a human watching is allowed only where a human would not hesitate: the normalized grocery name equals a product's name, or every word of it appears in exactly one product's name. Anything else opens the picker. The rule has no tunable threshold on purpose, so there is no number to re-guess when it misjudges. A name that matches to the letter is taken however many listings carry it, the first in the shop's own order: a shopper who wrote the product's own name has chosen, and the rule once demanded that name be unique, which left an AH loaf listed under two product numbers unlinked and showing twice in the dropdown. Only the looser branch has to be unique. Two listings a shopper could not tell apart, the same name at the same price and size, are one product to the rule and one row in the dropdown.
- The AI Runtime is not wired into this path at all, and the ladder leaves the seam where it would go — a reader that takes a page and returns candidates. Adding a model later is adding a rung, not rewriting the feature.
- Amended by ADR-0029: a per-unit price that is a product's only price, what a shop charges per kilo for something sold loose, is read as its Shelf Price. The per-kilo comparison printed beside a pack price is still not a price, and the rung that rejects it stays.
