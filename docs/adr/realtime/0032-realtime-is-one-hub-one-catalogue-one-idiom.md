# Realtime is one hub, one catalogue, one idiom

Norish's realtime layer had four ways to subscribe to Redis and two ways to write a subscription procedure. A per-WebSocket `SubscriptionMultiplexer` opened **one Redis connection per browser tab** and pattern-subscribed to everything a user could ever receive, with the household key pinned at connect time; the connection manager, the enrichment listener and the CalDAV listener each ran a hand-rolled subscriber loop of their own; and fifty-eight tRPC procedures existed as thirty-eight hand-written copies that stripped the envelope and cast the payload, beside twenty that kept it. Event shapes were declared three times — shared-server, tRPC router, client hook — and validated nowhere; the publish path fell back to a raw, un-enveloped message for any channel it could not parse, so the wire carried two formats and the client compensated with a proxy that let a handler read the payload either way, which is why the hooks carried forty `any`s. None of the transport had a test. A ~700-line copy of it sat unused in the queue package, and the one bug fix the live client needed had landed in the dead copy.

We deleted the layer rather than adapting it — an incremental migration behind compatibility shims was rejected outright, because the shim _was_ the debt — and built three things in its place. A **Realtime Catalogue** per domain, client-safe, declares every event once with its Scope (`household`, `user`, `policy`, `broadcast`, `internal`) and its zod payload schema; the server's domain object is `defineRealtimeDomain(catalogue)`, stateless, and its `publish` validates, stamps the operation id, and never throws to its caller, because a mutation that already committed must not fail on account of its announcement. A single **Realtime Hub** per process holds exactly one Redis subscriber connection, subscribes to exact channels by refcount, and fans out in-process through bounded queues; server-internal listeners register callbacks on it, tRPC subscriptions iterate it. One factory, `realtimeSubscription(domain, event)`, derives channels from the event's Scope and the subscriber's current identity, validates each event on the way out, and yields envelopes only, so a client handler always receives `(payload, meta)`.

A subscriber that falls behind is not buffered without limit. When its queue overflows, or when the hub's Redis connection reconnects and may have missed publishes, the subscription ends **Lagged** and the client's only reaction is to refetch that domain and resubscribe — ADR-0011's convergence rule applied to the server side of the pipe. Delivery stays at-most-once from Redis pub/sub; ADR-0034 puts a bounded Resume buffer in front of it without changing the guarantee. Besides the shim migration, we rejected per-connection subscribers (connections scale with tabs, not with the process), pattern subscriptions (they defeat refcounting and had the CalDAV listener parsing channel strings), a boolean return from publish (146 callers ignored it), raw non-envelope publishing (it forced the client shim), and `tracked()` ids without a buffer behind them (an id nobody can resume from is decoration).

## Consequences

- Adding a realtime event is one catalogue entry; the publisher, the procedure and the client type follow from it. A publish that fails its schema throws in development and test and is logged and dropped in production.
- Redis connections per process are the publisher, the hub, and BullMQ's — independent of connected clients.
- The `internal` Scope is for server-to-server facts (a recipe became usable, a connection must be invalidated); it is not subscribable from tRPC and is not buffered.
- A household-less user's household key is their user id; their household channel simply stays quiet. Subscriptions never wait for a household to exist.
- Lagged is the only failure a subscription reports. Queue overflow, Redis reconnect and every cursor failure (ADR-0034) look the same to the client, and the client refetches the domain and resubscribes — no toast, no per-event error handling.
- The client never suppresses its own echoes; handlers stay idempotent merges by identity, which is what makes Resume and refetch safe to apply on top of each other.
- The mobile app was parked rather than carried through the rebuild; it gets its own rewrite against the new layer.
- Bypassing the hub — a `createSubscriberClient()` outside `hub.ts`, a `PSUBSCRIBE`, a publish that skips the domain object, a second subscription helper — is a decision to reopen this ADR, not a shortcut.
