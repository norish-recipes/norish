# Resume is a bounded buffer, not a guarantee

ADR-0011 established that Redis pub/sub is not durable and that Recovery — refetching from server truth on WebSocket reconnect and on return from Offline — is the convergence guarantee. That remains true. This decision amends its sentence "Redis Pub/Sub delivery is not durable and therefore is not the cache-consistency guarantee" with a bounded first line of defence in front of it. Every publish whose Scope is not `internal` is appended to a per-channel Redis Stream — the channel with its `norish:` prefix replaced by `norish:stream:`, at most about a thousand entries, expiring twenty-four hours after its last write — in the same atomic Lua script that `PUBLISH`es it, and the stream entry id becomes the envelope's `eventId`, so a live event and its buffered copy carry the same id. Every subscription yields `tracked(cursor, envelope)`; the **Cursor** is an opaque string holding the subscriber's identity hash and one stream id per channel the subscription merges, and the tRPC WebSocket link resends the last one on reconnect. The server registers its live listeners, reads each channel's stream after its id, yields what was missed in order, then continues live, deduplicating by id at the seam. Every subscription begins with a **Cursor Mark** — a cursor delivered without an event — so a subscription that never saw an event is resumable too. If a cursor cannot be parsed, belongs to a different identity, is older than the buffer, or points before the oldest retained entry, the subscription ends Lagged and the client refetches the domain, the same reaction as queue overflow (ADR-0032).

We chose the stream-plus-publish script over three alternatives. Reading the streams instead of pub/sub (`XREAD BLOCK`) would need one blocking connection per set of streams and a restart of the call whenever a channel joined, which is the per-connection shape ADR-0032 just removed. `tracked()` over an in-process ring buffer would not survive a restart, which is exactly when a client reconnects. And two round trips — `XADD` then `PUBLISH` — would let a live event be observed before its buffered copy existed, breaking the "listen first, then read the stream" ordering the seam dedupe relies on; the script's one placeholder substitution is the price of atomicity. Recovery still runs on every reconnect today; Resume delivers the missed events first, in order, and is what a short blip benefits from most. Making Recovery's refetch conditional on a Lagged outcome is a possible later step, not part of this decision.

This is a delivery buffer, not a transactional outbox. `.scratch/recipe-enrichment/spec.md` forbids an outbox and that rule stands: a publish can still be lost if the process dies between the database commit and the stream write, and nothing reconciles the stream against the database. Internal events — a recipe became usable, a connection must be invalidated — are neither buffered nor resumable; their consumers accept the loss window their own specs document.

## Consequences

- Delivery is still at-most-once from the server's point of view; the client still converges by refetch. Handlers stay idempotent merges by identity.
- Two bounds, both fixed in code: about a thousand entries per channel and twenty-four hours per stream. A client away longer than either is Lagged and refetches; that is the intended outcome, not a failure.
- Cursors are opaque and identity-bound. A Scope Change (ADR-0033) invalidates them by construction; the client never inspects or stores them.
- Memory is bounded per channel by entries times payload size; recipe channels carry the largest payloads and are the ones to watch if the entry bound is ever raised.
- One Lua script owns append-then-publish. Splitting it into two round trips reopens the ordering assumption Resume relies on.
- The glossary term is Resume, not replay: Replay already means re-sending the Outbox, and the two must never be confused in a log line or a ticket.
- A `tracked()` id exists only because a buffer stands behind it; an event yielded without a resumable cursor reopens this ADR.
