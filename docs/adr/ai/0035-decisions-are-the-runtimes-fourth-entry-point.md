# Decisions are the runtime's fourth entry point, on their own provider

ADR-0024 closed with the bar a fourth entry point would have to clear: "a genuinely different kind of request, not a different feature making a kind that already exists." A Decision clears it. `decide` takes no Prompt and no schema, returns no text and no bytes, and leaves the structured-output strategy nothing to parse: typed questions go in — a Choice among named options, a Score on an ordered rubric, a Boolean — and a pick plus a full probability distribution comes back for each. **The AI Runtime gains `decide` beside `generateStructured`, `transcribe` and `generateImage`, and a Decision reads its own provider block, the Decision Model, rather than the server's AI provider.** The provider split is forced here too, and more completely than for images: no language-model provider Norish offers can answer a Decision at all. TypeSafe's Jev is a different kind of model — it generates nothing, and its probabilities are real rather than a number a language model wrote into a JSON field — reached through the AI SDK's TypeSafe provider and its `experimental_evaluate` call. The block follows the Image Generation shape (provider, key, model, endpoint) with one deliberate difference: **no fallback to the AI configuration's key**, because the provider never matches, so the block always carries its own. No timeout of its own, because ADR-0015's one AI timeout stands; no Generation Preferences, because Jev takes none, so ADR-0014 has nothing to drop.

**A Decision has no Prompt.** This is a scoped exception to ADR-0016's rule that every request starts from an administrator-editable Prompt, and the glossary's Prompt entry narrows from "every AI request" to "every language-model request" to record it. The reasoning: what an administrator tunes in a Prompt is wording; what would be tunable in a Decision is the option set, and the option set is the domain's — the four categories, the household's allergen list, the administrator's Cuisine vocabulary — which the code already owns as data. A question's instructions and descriptions are invariants the code depends on, the same standing as the system messages and Zod `.describe()` strings that already sit beside every Prompt. If a real need to tune a question's wording ever appears, that is a new decision, not a reason to start interpolating.

**Thresholds are code; uses are configuration.** How sure a kind must be before it acts on an answer is a named constant beside the question that produced it, with a test at the boundary — ADR-0014's spirit, no knobs Norish cannot explain, and the runtime returns every distribution as-is so it never holds a threshold of its own. _Whether_ a kind asks at all is an administrator's choice: the block carries a list of Decision Uses (auto-categorization, allergy detection, provenance, grocery linking, validating enrichments) chosen from one multi-select, every use selected the moment a Decision Model is configured, so enabling Jev enables everything it can do for a household and an administrator deselects what they do not want. A stored block without the list means every use, so a use added in a later release is on for everyone until deselected. Import triage has no switch: it serves Norish's own import algorithm, only ever makes an import cheaper or refuses a page that was never a recipe, and is not a household preference.

**The Decision Model is never required.** Every kind that gains a Decision keeps its language-model or heuristic path and takes it whenever the Decision Model is unconfigured, the kind's use is off, `decide` fails with any retryability, or the answer falls below the feature's threshold. A `decide` failure is a warn log and a fallback, never a feature failure: the kind either succeeds on the path it had or fails the way it failed before. Nothing a self-hoster has stops working because they did not sign up for a second provider, and nothing new breaks when that provider is down.

**The AI SDK line moved to 7 for it.** The TypeSafe provider and `experimental_evaluate` exist only on the 7 line (the V4 provider specification). The move was its own PR with no behaviour change; the temperature-fallback middleware was the one place it bit, and the transport tests caught it. TypeSafe's official zero-dependency client (`@typesafe-ai/sdk`) was the considered escape hatch — a raw client inside the provider boundary, as ADR-0015 already tolerates for transcription — kept in reserve for the case where the line move stalled. It did not, so `decide` is built on the SDK provider, and only `runtime.ts` and `providers.ts` import it: an API change on the experimental surface is a two-file change.

## Considered Options

- **One more member in the AI provider enum.** The smallest change on paper, and it makes "provider" mean two things: Jev cannot serve a single structured-generation request, so selecting it as the AI provider would break every import and every enrichment kind at once. Rejected.
- **A `decisionModel` field beside `model` and `visionModel`.** Reads as a second model of the same vendor, which it is not: it is a different vendor with its own key, its own endpoint and its own failure modes. Rejected for the reason ADR-0024 rejected a lone `imageModel` field.
- **A separate `packages/decisions`.** Rejected for the reason ADR-0015 rejected `packages/ai`: it would be a second seam that talks to a model, and there is exactly one.
- **Thresholds as settings.** Rejected: a threshold only means something beside the question and the fallback it governs, and a tunable one is a knob with no explanation attached.
- **The raw TypeSafe client instead of the SDK provider.** Kept in reserve, not chosen: the SDK provider keeps `decide` on the same transport, error classification and typed-error surface as the other three entry points, so ADR-0015's "one place that talks to a model" stays literally true.

## Consequences

- The runtime's promise narrows by one more word. It owns all AI egress and now reads four blocks: the AI block for structured generation, the video block for transcription, the image block for images, and the Decision block for Decisions. Only the first is what "the configured provider" means anywhere else in the product.
- ADR-0016 gains an exception, and the exception is bounded: a Decision's criteria labels are the answer schema and belong to the domain, and its instructions are code-owned. No parameter exists through which a feature could pass a finished prompt string, and none exists through which an administrator could edit a question.
- A converted kind reads as one function with two branches, in a fixed order: ask the Decision Model when it is configured and the use is on, and act when the answer is a Clear Case; otherwise take the path the kind had, unchanged. The coordinator, the queue, the lifecycle contract and Supplied Recipe Data precedence are untouched — a Decision changes _how a kind decides_, never _whether it runs_ or _what it may overwrite_.
- Every Decision-backed feature's tests mock `decide` and nothing else, and the E2E harness fakes TypeSafe's endpoint the way it fakes the OpenAI-compatible one, so a Decision under browser tests is a real loopback round trip like every other model call.
- The evaluation API is experimental on the SDK side. Accepted and contained to the two runtime files; a breaking change there is not a feature change.
- Enrichment Validation is the same entry point asked a second time, of the language model's own claims, between the answer and the write and never of stored data. Each check launches in one of two modes: tags, categories, Cuisines and Step Ingredients enforce from the start; the nutrition estimate, the provenance country and extraction's faithfulness are shadow — logged, nothing changed — until their disagreement rate is known, and promotion is a one-constant change beside the question with the rate in its comment.
- Grocery linking is the one place a Decision's probability sits beside a rule that refuses a threshold on purpose. `chooseUnmistakable`'s refusal is about a string-similarity number, which has no meaning a person can reason about; a Decision's probability is the model's stated chance that this product is the grocery, so `LINK_THRESHOLD` is a statement of how sure Norish wants to be before pricing a row on a shopper's behalf, and the name rule still runs first, unchanged.
- Adding a fifth entry point reopens this ADR, with the bar unchanged from ADR-0024.
