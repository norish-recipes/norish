# Norish never claims to know which parameters a model accepts

> **Rewritten 2026-10-06**, when image models met the same failure: the rule now covers every request Norish makes, and says where a table of model names may still appear (as a suggestion, never as a decision).

A self-hoster configuring `claude-sonnet-5` found every AI feature dead: Anthropic answers any request carrying `temperature` with a 400 for that model, so extraction failed before the model ever read the prompt (#514). Image models then did the same to drawing: DALL·E refuses the `low` quality tier, and `@ai-sdk/openai` adds `response_format` to every image model whose name does not start with `gpt-image-` or `chatgpt-image-`, which the GPT Image models refuse, so one reached under another name (an Azure deployment is named by its owner) fails on a parameter nobody asked for. Each time the cause was a table of model ids that lagged: the provider package's, or one Norish kept itself (a `ModelCapabilities` type, declared and never read, and later a quality tier chosen by model name).

**A model is the authority on what it accepts, and Norish learns it from the model's refusal.** A parameter Norish may go without is a Generation Preference: it is asked for, and on a request-shape refusal that names it the request is made again without it and the refusal is remembered for the life of the process. Today that is `temperature` for a language model, and `quality` and `response_format` for an image model, where the image fetch leaves a remembered one out of the body, so it reaches the parameter the SDK adds as well as the ones Norish passes. A request the model still refuses fails with the model's own words.

**A table of model names may suggest, never decide.** Where an administrator picks a model, the list offered may be narrowed by the names a provider's models go by: the Image Model field suggests OpenAI's `dall-e-`, `gpt-image-` and `chatgpt-image-` models and Google's Gemini image models, the names the provider packages themselves treat as image models, because a provider's model list says nothing about what each model can do. The field still takes any name typed into it. A stale table therefore hides a suggestion; it never refuses, reshapes or reroutes a request. Providers whose names say nothing (Ollama, LM Studio, a generic endpoint) are listed unfiltered.

We rejected keeping a capability table, which is the obvious fix and the wrong one. It would be a second copy of what every provider package already ships, updated on the release cadence of every provider at once, and it would still be empty where it matters most: `@ai-sdk/openai-compatible` (Ollama, LM Studio, every generic endpoint) sits in front of whatever model the operator runs, which no table can enumerate. Runtime learning has no such lag: the model is asked once, and its answer is believed.

## Consequences

- There is no capability type anywhere in the codebase, and no request is shaped by a model's name. Adding either back is a decision to reopen this ADR, not a gap to fill in. A suggestion list keyed on names is allowed only where the field still takes any value.
- Knowledge of a refusal is process-local and deliberately unpersisted: which parameters a model accepts is a property of the upstream service, not of this install, and it changes when the provider changes it. A restart re-learns it in one request.
- A refusal costs one rejected round trip per model, per parameter, per process. That is the price of not guessing, and it is paid once; a refused image request is not billed.
- Detecting a temperature refusal is a substring match on the provider's error, so a false positive is possible (Norish sends recipe text that talks about oven temperature): when the retry also fails, the caller receives the model's **original** objection with the retry's failure attached as its `cause`. An image refusal names its parameter in the provider's structured error (`error.param`), so it is read from there, the message's quoted name only as a fallback.
- Only request-shape rejections (400/422) are recovered. A 5xx, a timeout or a rate limit keeps its own error rather than being retried into a silently different request.
- Keeping the provider packages current remains the first line of defence, not a substitute for this: where a provider knows a model, it leaves the parameter out itself and no round trip is wasted.
- Which provider packages expose an image model at all (ADR-0024) is a fact about packages, not models, and stays a list.
