# Automatic provenance fills the group's gaps

Recipe Provenance shipped as one atomic precedence group: any substantive supplied value — a country, a region, a note, or a single Cuisine — suppressed the whole automatic run. The rule existed to protect coherence (the note explains the whole claim, and an AI paragraph beside a human-set country it argues against reads as two features fighting), but it protected far more than it needed to. The common case it punished is an import whose source stated nothing but a cuisine: that one value froze the group, so the country, the region, and the note stayed empty forever unless an editor asked for a manual run — which replaces the cuisine they supplied. **Automatic Recipe Provenance is now a gap-filler.** The group has four slots — the country with its written name, the region, the note, and the Cuisine set — and an automatic run keeps every supplied slot byte-for-byte while filling the absent ones. Coherence is defended where it actually lives, in what the model is asked and what the write accepts: inference receives the supplied slots as settled facts it must not contradict (an appended section, per ADR-0016), and the write refuses claim scalars beside a supplied country the claim disagrees with, so a disobedient or racing claim degrades to filling nothing rather than to arguing. We rejected keeping atomic suppression (it starves the majority case to prevent a conflict that constraint-plus-gate prevents more precisely), merging without telling the model (the write-side gate would then discard most of what was inferred, and a note computed against ignored facts is exactly the incoherence the old rule feared), and append-merging the Cuisine set (a supplied set is a curation decision; AI additions beside it are overrides in spirit, and nobody could untangle the authorship later).

## Consequences

- Eligibility inverts from "any value suppresses" to "a complete group suppresses": an automatic run enrolls while the country, the note, or the Cuisines are absent (`hasCompleteProvenance`), and the skip reason `supplied-data-present` now means the supplied data answers everything. `hasSubstantiveProvenance` remains the presence question — claim validation and rendering — and no longer decides precedence.
- The region and the written country name cannot demand a run: an absent region is a valid answer (a national dish has none) and the name is cosmetic (the endonym fallback renders without it). Both are filled opportunistically when a run happens anyway, the name only beside a country code the claim agrees with.
- The automatic write re-reads the stored group under a row lock and merges inside the transaction, so the absence recheck that lets newer supplied data win a race with AI survives at slot granularity: a value typed while the request was in flight is a supplied slot by the time the write looks, and a group completed in flight defers the whole claim — it does not even gain a region.
- Provenance stops being effectively write-once per recipe and becomes write-until-complete: Enrich All Recipes can now finish partially supplied groups across a library, which is the release-notes promise ("supplied data wins, only gaps are filled") that provenance previously broke.
- A manual run still replaces the entire group. Deliberate refresh semantics are untouched, as is the rule that an empty claim never erases stored provenance.
- The `.scratch/recipe-provenance/spec.md` "Eligibility and precedence" section describes the superseded atomic rule; this ADR is the current decision. Restoring whole-group suppression, or letting automatic runs replace a supplied slot, is a decision to reopen this ADR.
