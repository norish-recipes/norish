# Page Renderers are tried in a fixed order, and the solver never gets tokens

URL imports, Store Visits and the Instagram caption fallback all read some pages that a plain fetch cannot, so they hand those pages to a Page Renderer. Until 0.26 the only Page Renderer was Obscura. That stopped being enough: Cloudflare challenges Obscura on sites it serves to an honest plain request (#641), Akamai shows Obscura its block page on Allerhande, and operators already run FlareSolverr or Byparr for other services. **An administrator now switches on Obscura, a Chromium browser (any Chromium with a CDP endpoint) and a FlareSolverr-compatible solver separately, in one admin setting seeded from env on first boot. Every caller fetches plainly first, then tries Obscura, then the Chromium browser, then the solver, in that fixed order, and moves on only when a renderer comes back with no HTML or with a bot check.** Site Auth Tokens go to Obscura and the Chromium browser, which keep them to their site. The solver never gets them: when the chain reaches it, the request goes without them, and the log says the tokens were withheld.

## Considered Options

- **One engine only.** This was the previous decision. It cannot get past a site whose bot check reads Obscura, and an administrator who already runs a solver has no way to use it.
- **Racing both renderers.** Every render would pay for a solver browser (FlareSolverr and Byparr launch a fresh browser per request, about 6 s each). Every Store Visit refresh would double its browser launches. Aborting the request does not stop the solver's browser either. Meanwhile the case racing helps with is already fast: Obscura returns a challenge page within seconds, and the bot-check test fails it at once.
- **An admin-orderable chain, a remembered renderer per host, or a host-to-renderer list.** One wasted Obscura attempt on a background job does not justify a setting or state that goes stale. Remembering per host is the place to add it if those seconds ever matter.
- **"No recipe found" as a failure.** That would re-run parsing, and pay for AI, once per renderer. The fetch layer judges from the HTML alone.
- **Sending cookies to FlareSolverr.** FlareSolverr takes only `{name, value}` cookies and sets them on whichever host its first load ended on, so a redirect off the site would carry the session with it. Byparr drops cookies altogether. Neither solver accepts headers.
- **Camoufox as the second browser.** It speaks Playwright's own protocol rather than CDP, so its server and Norish's client would have to move version for version, and upstream ships no runtime image to repackage.
- **CloakBrowser or Fortress as the shipped browser.** CloakBrowser's free build read Allerhande, but both binaries are licence-gated and cannot go into a Norish image. An administrator can still point the Chromium browser at either. Norish ships fingerprint-chromium instead, which is BSD-3.

## Consequences

- **Private addresses.** Neither solver has a private-network deny, and neither authenticates `/v1`.
  - An **Allow private addresses** admin switch, off by default, makes Norish refuse a target that resolves to a loopback, RFC1918, CGNAT, link-local or other non-public address. The refusal happens before the plain fetch, and before the Chromium browser and the solver, which share one check per render.
  - Inside the Chromium browser, with the switch off, document requests are paused through CDP `Fetch` before they are sent. Each redirect hop is checked like the target, and a refused hop fails the render, as does a hop whose name does not resolve, so Chromium never resolves a name Norish could not check. Subresources such as images and XHR are not checked, and neither is DNS rebinding, because Chromium resolves the name again after Norish has checked it.
  - The switch does not cover redirects and DNS rebinding inside the solver's browser, or image downloads.
  - Obscura keeps its own deny regardless of the switch, because it is enforced at DNS resolution and built into the shipped image. `--allow-private-network` and `OBSCURA_ALLOW_PRIVATE_NETWORK` appear nowhere. With the switch on, a LAN recipe site gets through the plain fetch, the Chromium browser or the solver, Obscura refuses it, and the chain moves on.
  - The off default is a change for upgraders, because the plain fetch used to reach private addresses.
- **Tokens in the Chromium browser.** Cookies are set over CDP for the token's domain, `secure`, before the navigation, and Chromium keeps them to that domain. Header tokens go through CDP `Fetch`: requests on a token's https site are paused, and each continues with the header tokens whose domain its host is on. Chromium pauses every redirect hop as its own request, so a redirect off the site carries no header. Playwright's `route` was rejected because its header overrides follow redirects: in testing, a header reached postman-echo.com from httpbin.org. No browser gets tokens for an http page.
- **Status.** Both solvers hard-code `status: 200`. A solver's render therefore reports a null status and never names a refusal, and the import fails with its usual fetch failure.
- **Settling.** Store Visits' settle callback reaches Obscura and the Chromium browser. Without one, Obscura's page is read once it loads. The Chromium browser's page is read once it is not a bot check, because Akamai answers every new browser on Allerhande with a challenge that reloads into the recipe seconds after load. It is also read only once its document has finished loading, since a page read mid-stream can have its title and no recipe. The wait is the same 15 s either way. A solver's answer is read once: Byparr waits for `networkidle`, and FlareSolverr waits for its challenge to clear.
- **Bot-check test.** There is one bot-check test, in `parser/fetch.ts`. It catches Cloudflare's challenge markup, a small page with no title or with a block page's title such as Akamai's "Access Denied", and a renderer's 401, 403 or 429. It is shared by every caller.
- **Failure.** A render that fails at every enabled renderer fails the import. Nothing retries outside the chain. With every renderer off, Norish fetches plainly only, and the Instagram caption fallback is skipped. A browser that cannot be reached counts as no HTML and is logged at error level, with its endpoint's query string left out.
- **Shipped defaults.** Compose ships Obscura switched on. The Chromium browser is a commented-out `chromium` service, and FlareSolverr and Byparr are commented-out alternatives on port 8191. Upgraders' existing `OBSCURA_ENDPOINT` and `OBSCURA_CDP_TOKEN` seed the setting, `CHROMIUM_BROWSER_ENDPOINT` seeds the Chromium browser switched on, and after that, admin settings own it.
- **Obscura stays Norish's own artifact.** `docker/obscura/` repackages the pinned `-stealth` release archive of the norish-recipes fork. `pin.env` records the release and the image tag together, and the publish workflow refuses to overwrite a tag. Stealth is not configurable, and neither is anything else about the browser. Upstream's image was rejected because it is built `--features render` and carries none of the stealth build's BoringSSL symbols. A from-source build was rejected because repackaging buys the same binary.
- **The Chromium image is Norish's too.** `docker/chromium/` repackages a pinned fingerprint-chromium release the same way. It is amd64 only, because upstream builds Linux for x86_64 only. Chromium runs with `--no-sandbox`, because Docker's default seccomp profile refuses its sandbox, so the container is the boundary, as it is for Obscura.
- **The Chromium browser's endpoint is dialled by address.** Chromium's DevTools server refuses a Host header that is not an IP address or localhost, so Norish resolves an http or ws endpoint's name and dials the address. It takes an IPv4 address first, where the shipped image listens, and then the lowest, so a name whose records rotate keeps one connection. A changed address replaces the connection. `localhost` and `*.localhost` are dialled as given, since Chromium's DevTools listen on 127.0.0.1 and `localhost` may resolve to `::1`. An https or wss endpoint is dialled as given too, because a hosted browser sits behind a TLS proxy without that check.
- **The boundary stays narrow.**
  - `parser/browser-connections.ts` holds one cached connection per CDP renderer, keyed by endpoint and token, and `parser/fetch.ts` holds the per-fetch context and the chain.
  - The chain is three named calls in a fixed order. There is no engine registry and no `BrowserEngine` interface. Obscura and the Chromium browser share one browser render, and each passes its own step that prepares the page.
  - Whether the HTML holds a recipe is still the parser's and the AI fallback's question. The bot-check test reads the HTML that comes back and never waits on a selector.
- **One Playwright generation.** Runtime `playwright-core` tracks `@playwright/test`. The E2E runner's Chromium is acceptance tooling: one test points the Chromium browser at it.
- **Page Renderer is now a glossary term**, because administrators choose it. Obscura, the Chromium browser, FlareSolverr and Byparr are its values, not glossary terms.
